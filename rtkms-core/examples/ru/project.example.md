# Система управления требованиями, задачами и знаниями "RTKMS"

## Обзор проекта
RTKMS - это система, предназначенная для управления требованиями, задачами и знаниями в проектах разработки. Она обеспечивает структурированный подход к документированию требований проекта, отслеживанию задач и управлению базой знаний.

## Подход к разработке
RTKMS использует текстовый подход к управлению артефактами проекта, при котором весь контент хранится в файлах Markdown. Это обеспечивает:
- Контроль версий через Git
- Удобное редактирование с помощью любого текстового редактора
- Переносимую структуру проекта
- Кроссплатформенную совместимость

## Система управления
Этот проект использует систему управления требованиями, задачами и знаниями (RTKMS) для организации требований, отслеживания задач и управления знаниями проекта. Для получения дополнительной информации об этой системе обратитесь к каталогу `rtkms/rules`.

## Дополнительная информация
Для получения дополнительной информации об использовании системы обратитесь к файлу workflow.md и правилам в каталоге rtkms/rules. 

## Цели проекта
- Создать легкую, переносимую систему управления требованиями
- Создать эффективный механизм отслеживания задач
- Сформировать структурированную базу знаний проекта
- Обеспечить интеграцию с ИИ-ассистентами
- Поддерживать ведение текстовой документации
- Поддерживать документирование алгоритмов с помощью диаграмм на PlantUML

## Этапы проекта
Проект разделен на несколько этапов. 
Подробная информация о каждом этапе находится в файле `stages.md`.

- S01: Разработка идеологии системы и базовой структуры. Первичная отладка скриптов.
- S02: Расширенные возможности.
- S03: Отладка, документирование и локализация на english.
- S04: Релиз.

## Список требований к проекту
- В конце каждого этапа 2 необходимо выполнить рефакторинг кода
- В конце каждого этапа 3 должна быть выполнена ревизия накопленного опыта и методик

## Требование к коду:
- Код должен быть написан так, чтобы его можно было прочесть с минимумом комментариев
- Код должен быть простым и оптимальным
- Код должен быть разбит на несколько файлов, если в нем присутствует больше 1 класса или больше 200 строк

## Требование к документации:
- Документация к исходным кодам должна содержать planuml диаграммы, описание кода, инструкции
- PlantUML диаграммы должны использовать простой синтаксис без украшений и цветов
- PlantUML диаграммы должны проходить проверку с помощью ${utils_path}/validate_puml.sh
- Описание кода должно быть простым и не содержать сам код
- Инструкция должна содержать краткое описание, что делает код, что использует для запуска, инструкцию использования и примеры

## Требование к накоплению опыта:
- Вся важная информация об опыте ведения проекта, разработки и применяемых методах должна быть сохранена явно в отдельной папке
- Накапливать опыт необходимо, чтобы повысить эффективность разработки с помощью LLM
- Опыт может быть портирован в другие проекты

## Требования к управлению задачами:
- Задачи этапа формируются в начале каждого этапа
- В конце каждого этапа формируются предложения для добавления в backlog
- Запрещается автоматически изменять задачи в backlog, возможно только сделать предложения для пользователя
- Задачи из backlog могут быть взяты на следующий этап
- В проекте должно вестись управление задачами по шаблонам принятым в начале проекта
- В конце каждого этапа должен быть сделан отчет в отдельном файле по шаблонам принятым в начале проекта
